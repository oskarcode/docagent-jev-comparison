1. Project From 10,000 Feet

The problem: research agents often choose tools from wording alone. This experiment asks whether a small classifier that recognizes common task shapes can route the Jev lane to a more suitable tool while keeping every other variable equal.

A React page submits the same prompt twice with fresh conversation IDs. The Baseline agent chooses directly from identical tools. The Jev agent first calls classify_research_request, then follows its returned route. The UI shows answers, tool traces, timing, and errors side by side.

Core invariant: the lanes differ only by Jev classification and routing instructions. Fresh conversation IDs prevent earlier answers from affecting later comparisons.

Technology map

TypeScript is the implementation language. Vite builds React. Hono serves the app and diagnostics. Flue supplies agent endpoints and streaming events. Cloudflare Workers hosts the combined frontend/backend. AI Gateway fronts model calls, and remote MCP servers supply research tools.

Check yourself: Why are two new conversation IDs more important than using the same visible question?
Answer They isolate lane memory, so prior turns cannot become an uncontrolled variable.

3. End-to-End Flows

Baseline comparison sequence

  1. App.runComparison() creates two UUIDs and starts both lane promises concurrently.
  2. runLane("baseline", id) creates AgentClient({ agentId: "baseline-research", conversationId: id }).
  3. The Flue client posts to the generated mount at /agents/baseline/*; the mounted Hono router resolves the baseline agent and conversation.
  4. DocAgent.respond() asks the model to select from research tools and streams status/tool/text events.
  5. The client consumes the event stream; projectActivity() normalizes trace rows and collectAnswer() extracts only assistant text.
  6. React independently renders trace, answer, elapsed time, and any lane-local error.

Jev comparison sequence

  1. The browser starts Jev concurrently at generated /agents/jev/* with its own UUID.
  2. The Jev prompt requires classify_research_request before research.
  3. The tool calls the configured classifier model through fetchAI(), parses structured JSON, and returns a route such as direct answer, web search, or multi-source research.
  4. The agent follows that route using the same research MCP available to Baseline.
  5. The same Flue event stream and frontend projection code render the Jev result.

Failure behavior

A classifier/model/tool failure becomes a visible tool or lane error rather than silently changing the Baseline lane. Promise.all() waits for both lane wrappers, while each wrapper catches its own exception so one failure does not erase the other result.

Check yourself: Where are the Flue endpoints defined?
Answer They are generated by each serveAgents(...).hono() mount in src/app.ts, not handwritten as individual POST handlers.

4. Components and Responsibilities

App.tsx
Orchestrates concurrent runs and renders comparison state.
activity.ts
Converts untrusted stream events into safe UI projections.
app.ts
Builds runtime config, mounts generated agent routers, serves diagnostics/assets.
research-agent.ts
Defines the shared Flue agent and lane-specific configuration.
jev-research-router.ts
Defines classifier schema, model call, parsing, and tool.
registry.ts
Centralizes allowed model and MCP identifiers.

Why these boundaries matter

Routing logic stays out of presentation code; runtime secrets stay out of browser bundles; event projection is pure and testable; registry values have one source of truth. The shared agent class prevents accidental lane drift.

Build and test support

Vite configs connect frontend development to the Worker API. Vitest runs the pure unit suites. prepare-deploy.mjs derives a temporary deployment config without mutating the checked-in Wrangler file.

5. Data, State, Interfaces, and APIs

State ownership

React owns input and run state and stores model preference plus the latest completed result in local storage. Flue durable conversations own lane histories. Worker environment values own provider, classifier, and optional MCP credentials.

Key shape

ComparisonRun = { pairId, model, baselineConversationId,
jevConversationId, prompts, turnId, phase }

HTTP surface

GET /api/health reports liveness. POST /api/comparisons validates a model and returns paired IDs. Generated Flue protocol routes live at /api/agents/baseline/:id and /api/agents/jev/:id.

8. File-by-File Code Learning

Use these walkthroughs with the exact source tree above. Each topic explains where the file enters execution, its main symbols, side effects, connections, and change risks.

Add or change a research tool

Change src/agents/research-agent.ts for both lanes, then verify the tool list remains equal. If the route vocabulary changes, update jev-research-router.ts and its tests. Do not give Jev exclusive research capability.

Add a UI metric

Define the projection in activity.ts, test malformed and valid events, then render it in App.tsx. Keep stream parsing outside JSX.

Change deployment configuration

Update wrangler.jsonc and, when the value belongs to the allow-list, registry.ts. Check whether prepare-deploy.mjs must copy or transform it.

Safe change checklist

  1. Preserve lane symmetry and fresh IDs.
  2. Trace the change through browser, generated Flue route, agent, provider/MCP, and stream response.
  3. Add focused tests at the parsing or registry boundary.
  4. Run npm run check.
  5. Inspect generated deployment config without committing it.

Beginner practice

Start by adding a safe field to /api/config, display it in the UI, and test the registry lookup. Then try adding a new classifier route while leaving the research tools unchanged.

Final check: What is the first question to ask before changing one lane?
Answer Does this introduce a difference beyond the classifier and routing instructions? If yes, it invalidates the comparison unless the experiment is deliberately redesigned.
